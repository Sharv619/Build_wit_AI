# PRD: Pilly v2 — Backend-Hardened Responsible AI Medication Support MVP

**Project Name:** Pilly / MediMate Voice
**Version:** v2
**Owner:** Himanshu Lade
**Status:** Implementation PRD
**Primary Goal:** Turn the existing hackathon MVP into a backend-hardened, safety-bounded, portfolio/business-ready medication support prototype for seniors and caregivers.

---

## 1. One-Liner

Pilly is a Firebase-backed medication support prototype that helps seniors respond to event-based medication reminders while giving caregivers visibility into missed doses, refusals, snoozes, and help requests — without providing diagnosis, medication advice, dosage advice, or clinical decision-making.

---

## 2. Product Positioning

Pilly is not a generic medication reminder app.

Pilly is a **post-discharge medication support workflow prototype** for seniors and family caregivers.

The core product insight:

> Stable daily medicines may already be handled through Webster Packs, but temporary post-hospital prescriptions, antibiotics, pain medication, or medicines kept outside the pack can create confusion. Seniors need simple routine-based support, and caregivers need enough visibility to help without making the senior manage a complex app.

---

## 4. Target Users

### 4.1 Senior

A senior who needs simple medication reminders tied to familiar routines.

Examples:

* Breakfast
* Lunch
* Dinner
* Bedtime
* Leaving home
* Post-discharge check-in

The senior should not need to understand a complex medication app.

---

### 4.2 Caregiver

A family member or trusted caregiver who needs visibility into:

* Whether medication was taken
* Whether medication was snoozed
* Whether the senior refused
* Why the senior refused
* Whether help was requested
* Whether a routine event ended without a final response
* Whether leaving-home medicines should be taken along

---

### 4.3 Future Pharmacy / Provider Context

Pilly may later support pharmacy/provider workflows around temporary medicines and medicines outside a Webster Pack.

For v2, this remains a product direction only.

Do not implement a production provider portal in v2.

---

## 5. Safety Boundary

This is mandatory.

Pilly must **not**:

* Diagnose conditions
* Recommend medication
* Recommend dosage changes
* Tell a senior to skip medication
* Tell a senior to take extra medication
* Replace doctors, pharmacists, nurses, or caregivers
* Act as emergency triage
* Use real patient data in the demo
* Use AI for medical decision-making

Pilly may:

* Classify simple senior responses
* Record medication status
* Create caregiver-visible notifications
* Show static urgent safety guidance
* Ask the senior/caregiver to contact appropriate human support
* Support an existing medication schedule entered by a caregiver/demo seed

## 8. Core v2 Product Workflow

The v2 golden path must support this flow:

```text
Seed demo household
        ↓
Create senior and caregiver demo users
        ↓
Create routine events
        ↓
Create medications assigned to events
        ↓
Senior sees current event reminder
        ↓

        ↓
Cloud Function classifies response
        ↓

        ↓

        ↓

        ↓

```

## 12. Urgent Phrase Handling

The system must detect urgent phrases and respond with static safety guidance only.

Examples of urgent phrases:

```text
chest pain
cannot breathe
fell
dizzy
emergency
severe pain
confused
passed out
```

Expected behavior:

* Do not call Gemini for medical advice.
* Do not generate a dynamic clinical response.
* Return static safety guidance.
* Log the response.
* Create caregiver-visible notification.
* Mark the item as requiring human follow-up.

Static safety copy must be calm, non-diagnostic, and direct.

Example:

```text
This may need urgent human help. Please contact your caregiver, pharmacist, doctor, or local emergency service if you feel unsafe or symptoms are serious.
```

## 15. Cloud Function Requirements

### 15.1 seedDemoData

Purpose:

Create a demo household with:

* Senior user
* Caregiver user
* Routine events
* Example medications
* Example post-discharge medicine
* Example Webster Pack medicine

Acceptance criteria:

* Can run repeatedly without corrupting demo state.
* Creates deterministic usable demo data.
* Returns household/user IDs or enough metadata for the frontend.

---

### 15.2 classifyMedicationResponse

Purpose:

Classify senior response text into supported response statuses.

Inputs:

```text
rawResponse
medicationId
routineEventId
householdId
```

Outputs:

```text
responseStatus
refusalReason
urgentPhraseDetected
safetyMessage
classificationSource
confidence
```

Requirements:

* Gemini must be server-side only.
* If `GEMINI_API_KEY` is missing, deterministic fallback must work.
* Urgent phrases must trigger static safety guidance.
* Must not generate medical advice.

---

### 15.3 recordMedicationResponse

Purpose:

Record a senior medication response.

Responsibilities:

* Validate household context.
* Classify response if needed.
* Write medication log.
* Create notification if needed.
* Return updated status.

Must handle:

```text
taken
snoozed
refused
help_requested
urgent_phrase
unknown
```

---

### 15.4 completeRoutineEvent

Purpose:

Mark an event complete and create missed-dose alerts for active medications assigned to that event that do not have a final response.

Requirements:

* Only check medicines assigned to the completed event.
* Do not create missed-dose alerts for unrelated medicines.
* Do not duplicate alerts if function is called more than once.
* Write caregiver-visible notifications.

---

### 15.5 simulateLeavingHome

Purpose:

Simulate leaving-home context and notify caregiver/senior about medicines that should be taken along.

Requirements:

* Identify active medicines tied to `leaving_home`.
* Create notification.
* Return medicines to take along.
* Do not create medical advice.

---

### 15.6 generateReminderCopy

Purpose:

Generate safe reminder text.

Requirements:

* Copy must be supportive.
* Copy must not shame, guilt, or manipulate.
* Copy must not include dosage advice beyond existing stored instructions.
* Must work without Gemini using template fallback.

---

### 15.7 generateMissedDoseAlert

Purpose:

Create caregiver-safe missed-dose alert copy.

Requirements:

* Static or template-based output preferred.
* No diagnosis or medication advice.
* Encourage caregiver follow-up.

---

### 15.8 processScriptUpload

Purpose:

Process uploaded prescription/script file into candidate medicines.

v2 requirements:

* Candidate output only.
* Caregiver must confirm before records are created.
* No real prescription data should be used in public demo.
* May remain stubbed if not part of golden demo.
